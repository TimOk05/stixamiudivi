# Правила разработки сайтов

## Область действия
- Эти инструкции действуют для этой папки и всех сайтов внутри неё. Учитывай дополнительные `AGENTS.md` конкретного сайта.
- Общайся с пользователем по-русски. Язык сайта определяй по заданию и существующему контенту.

## Автоматический выбор библиотек
- Самостоятельно выбирай и подключай подходящие инструменты в рамках задачи разработки. Обычная установка необходимых зависимостей не требует отдельного согласования.
- Сначала используй возможности существующего стека. Не переводи готовый HTML/CSS/JavaScript.
- Для нового сайта выбирай минимальный достаточный стек. Статические страницы услуг могут оставаться на HTML/CSS/JavaScript.
- JS код пиши без ООП, без сторонних библиотек.
- При необходимости серверной части делай её на ванильном PHP без ООП, без сторонних библиотек.
- Tailwind CSS рассматривай для новых проектов и проектов, где он уже используется. Наличие Tailwind не заменяет работу над композицией и типографикой.
- Lucide предпочитай для интерфейсных иконок. Используй подходящий пакет или отдельные SVG, единый размер и толщину линий; не загружай весь каталог ради нескольких иконок. Иконкам-кнопкам давай доступное имя, декоративные иконки скрывай от скринридеров.
- daisyUI выбирай, когда нужны готовые компоненты и темы поверх Tailwind, в том числе без React. Настраивай тему под конкретный бренд.
- Обычно выбирай одну основную систему компонентов. Не добавляй несколько UI-библиотек с дублирующими функциями без конкретной необходимости.
- Перед установкой проверяй актуальную официальную документацию и совместимость с версиями проекта. Сохраняй зависимости и lockfile; не обновляй несвязанные пакеты.
- Используй доступные подключённые инструменты и MCP, если они помогают задаче. Если MCP отсутствует, используй официальную документацию и CLI; отсутствие MCP не мешает работе с библиотекой. Не считай упоминание сервера в этом файле его подключением.

## Визуальное качество
- Перед созданием нового дизайна сформулируй краткое визуальное направление: характер бизнеса, палитра, типографика, композиция, изображения и характер анимации. При локальной правке сохраняй существующий стиль.
- Realtime Colors и Coolors используй при необходимости для поиска и просмотра палитр. Переноси выбранные цвета в CSS-переменные или токены темы; подключение этих сервисов к работающему сайту не требуется.
- Задавай цвета по назначению: фон, поверхность, основной текст, вторичный текст, акцент, граница и состояния. Проверяй контраст реальных сочетаний, включая hover, focus и disabled.
- Используй согласованную шкалу отступов, размеров текста, ширины контента и скруглений. Обеспечивай читаемость длинного текста и ясную иерархию заголовков.
- Создавай композицию под конкретный бизнес. Готовые компоненты должны поддерживать стиль сайта; избегай одинаковых секций и декоративных эффектов на каждом проекте.
- Используй релевантные изображения с корректными пропорциями, адаптивными размерами и разумным весом. Проверяй обрезку изображений на мобильных экранах.
- Делай адаптивную вёрстку, семантический HTML, заметный клавиатурный фокус, подписи полей и понятные состояния ошибок. Учитывай уменьшение анимации в настройках пользователя.
- Сохраняй достоверность контента: не выдумывай отзывы, рейтинги, награды, контакты и факты о бизнесе. Демонстрационные данные обозначай явно.

## Обязательная проверка через Playwright
- При создании сайта и изменениях вёрстки, стилей или поведения запускай сайт локально и проверяй затронутые страницы через Playwright. Изменения только документации не требуют браузерной проверки.
- Сначала используй имеющуюся конфигурацию, тесты и команды проекта. В `stalybridge-nails` и `demosite-github` уже есть `playwright.config.js` и команда `npm test`; в остальных проектах проверяй текущий `package.json`.
- Если Playwright отсутствует, подключи его как devDependency нужного сайта и установи Chromium, когда это необходимо. Можно использовать уже доступный Playwright-инструмент, если он позволяет выполнить те же проверки. MCP для этого не обязателен.
- Прочитай настройки локального сервера, порта и базового пути. Не предполагай, что сайт открывается в `/`, и не используй случайно сервер другого сайта на занятом порту. Если нужно, выбери свободный порт.
- Для нового сайта или существенного редизайна проверь ключевые страницы при ширинах около 390, 768 и 1440 px. Для небольшой правки проверь затронутую страницу на мобильной и настольной ширине и дополнительные состояния по необходимости.
- Дождись загрузки шрифтов и изображений. Сделай скриншоты, открой и визуально просмотри их: создание файла скриншота само по себе не является визуальной проверкой.
- Проверь отсутствие горизонтальной прокрутки, наложений, обрезанного текста, сломанных изображений, неправильных отступов и недоступных элементов под фиксированной шапкой.
- Проверь применимые взаимодействия: мобильное меню, навигацию и якоря, основные кнопки, диалоги, формы и их валидацию, клавиатурную навигацию и закрытие меню/диалогов. Проверка форм не должна создавать реальные заявки или отправлять сообщения во внешние сервисы.
- Просмотри ошибки консоли, необработанные исключения и неудачные запросы ресурсов сайта. Отличай ошибки проекта от недоступных внешних сервисов.
- Исправь найденные проблемы и повтори затронутые проверки. После успешной проверки не повторяй полный набор без новых изменений или причин.
- Выполни применимые существующие команды `check`, `build` и тесты, если они определены. Для новых значимых интерактивных функций добавляй полезные проверки поведения; не создавай тесты, просто повторяющие реализацию, ради мелких косметических изменений.
- Временные скриншоты, трассировки и отчёты сохраняй вне исходников и публикуемой сборки, например во временную папку с отдельным именем сайта. Не коммить их без необходимости.
- Если браузерную проверку выполнить не удалось, укажи конкретную причину и какие проверки остались невыполненными. Не сообщай, что сайт проверен, если выполнены только сборка или чтение кода.

## SEO

- При создании сайта сразу проектируй и внедряй AI оптимизацию в соответствии с лучшими практиками, чтобы ИИ агенты легко находили нужную информацию на сайте.
